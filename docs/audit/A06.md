Auditor: cell C-047 (independent reviewer; did not write these parts). Line numbers are those of the files before this audit's edits and are approximate (+-5). ## Checked

- 05b, all six machines (Job, Cell/Lease/Submission, member tier and status, template review, service review, appeal) plus Escrow and Reservation: every state is reachable and has an exit or is terminal, except the service `suspended` (review_lapsed) dead end (finding 6) and the appeal `awaiting_second_review` withdrawal gap (logged). Every transition row has a guard, side effects, a ledger column and an audit-log entry.
- 05b state and event names against S0.9.2 to S0.9.8: equal, except the additions already listed as convention additions 3 to 9 (JT-19 from `screening`, `cells_exhausted`, `lease.extended`, MS-05, `template.approval_recorded`, SVT-06 from `in_review`, CT-18 reuse of `cell.declined`); each addition is declared and justified.
- 05b ledger effects name entry types and keys (`escrow_hold`, `transfer`, `levy`, `refund`, `mint`, `reversal`, `grant`, `reserve_donation`, `escrow_release`) and match S0.8.5, with the exceptions in findings 29 and 30.
- 05b arithmetic: reliability thresholds with a = b = 1 (3 clean observations for 0.80, 18 for 0.95), lease deadlines (1,200 + 600 + 120 = 1,920 s), the FD 3.3 example (240 primary cells, 24 pool cells, 264 payouts, levy 12,000,000 ucr, refund 0), closing identity in `settle()` (held = payouts + levy + refund holds algebraically once `pool_ok` is fixed), AC-race-04 (3 - 2 = 1) and AC-race-17 (300 credits against two 276 escrows).
- 05b policy tightening, service revoked, kill switch, cancel, overrun and expiry: each has a transition and a fan-out row (5.22.1, 5.22.2, SVT-05..09, JT-15, JT-18..20, CT-04, credit expiry sweeper).
- 05b races: GU-01..GU-14, RC-01..RC-32, E1..E7, lock order 5.29.2 (acyclic once the MintBudget row is placed, finding 24), settlement exactly-once, crash recovery table for every worker in 5.29.10 (each row has a recovery cell; the idempotency-record gap is finding 9). Overclaims in GU-02, GU-07, GU-12 corrected.
- 09 submit pseudocode SC-01..SC-22: order, reject code per check, nonce hash-only storage, constant-time compare, nonce lease-bound and single-use through `nonce_consumed_at`, expiry through `grace_until`, size limits (stream cut at cap + 1 byte), strict JSON, normalization procedure and the character class table (13 rows), escaping per output context (14 contexts), never-execute table (8 forbidden mechanisms), detector classes L, C, A with stated limits, duplicate detection (D1..D4, MinHash arithmetic: 1 - (1 - 0.95^4)^32 miss probability about 4e-24, so the stated bound holds), timing signals with stated limits, attestation fields, copy keys, parameter list (17 added parameters counted and matched to the list).
- 09 and the no-read rule: E1..E6 exclude any read of the volunteer's chat page, DOM, provider session or credentials; the clipboard is read only by a tap on the Paste button or by the volunteer's own paste event (text/plain only). No path in 05b or 09 reads a provider page, stores a provider session, or submits on a volunteer's behalf.
- 09 against S0: reject codes (one addition, `reject.attestation_invalid`, declared), error codes and statuses, `Idempotency-Key` rules, size parameters (32,768 against 18,000), UTC and server-clock rule, `declared` wording (no "guaranteed" in user-facing copy).
