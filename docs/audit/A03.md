# Audit A03: spec/14-launch-gates.md and spec/07-policy.md

Reviewer: independent adversarial read (cell C-044). Files audited: `spec/14-launch-gates.md` (S14), `spec/07-policy.md` (S7). References: `spec/00-conventions.md` (S0), Founding Document (FD), `docs/source/prompt.md`, `docs/decisions.md`. Line numbers in the findings table are approximate pre-edit positions.

## Checked

- Top constraint, building versus launching. Enumerated every path that can admit a member, create a job, mint credit, lease a cell or show a cell. Result: `member.created`, `ledger.mint` and `cell.leased` were guarded; the cell listing, Commons job creation, `job.waitlist_released`, `reservation.activated` and the launch switch at lease time were not (findings 2, 3). Added a path-by-capability table (S14.9.2) mapping each path to (a) global switch, (b) service state, (c) reviewer-recorded flags with a saved terms copy.
- Bypass classes: seeds and migrations (database triggers were promised in 14.4.7 but never listed; findings 5), admin, founder, test and `system` principals (guards test the switch, not the caller; production refuses test admins), Commons backlog creation (finding 3), background jobs (same transaction guard), fail-open defaults (a lost seed row of `kill.all_minting` was treated as impossible, finding 7), revoke-versus-lease race (no isolation rule, finding 6), fresh database state (all switches `false`, no authorization, zero approved services; confirmed against INV-P08 and S0.10.6 table C).
- Exit rule of FD 8.3 as a machine check: `evaluate_switch` read end to end. Confirmed the G0 service count and the fallbacks (S14.7.4) match FD 8.3 wording; found that G2, G3 and G5 items were never evaluated and that a zero `launch.min_approved_services` passes with no service (findings 1, 9, 12, 13).
- Two-person rule: SO-1..SO-8, the sign-off digest bound to a WebAuthn challenge, `LaunchAuthorization` with `proposed_by <> approved_by`, kill-switch release by two admins. With ONE admin nothing can be signed, opened or released; this was implicit and is now stated (S14.8.6, AC-launch-51). S0 allows `launch.min_signoffs` = 1, which conflicted with SO-4 (finding 8).
- Service gate `SG` against S7.10.1 to S7.10.6 and S0.9.6: grace period, terms copies per round, flag reading, field names (findings 4, 10, 11).
- S14 catalog: 12 `g0.svc.*` items counted and match AC-launch-41; G0 (a) to (k), counsel questions, fallbacks i to iv, G1 to G5 items traced to FD 8.3 sentence by sentence; no provider fact, legal conclusion or measured value appears in the catalog.
- Ground rule 2 in both files: no provider named, no URL parameter, price, limit or regional fact stated; every dependency is a `FlagAnswer`, `TermsCopy`, adapter field or `LaunchGateItem` evidence marked [V]. No automation of a volunteer account in S7.12.6 or the adapter rules (`prefill_url_template` only substituted, human presses Send).
- Policy rules R1..R10 as data: read all ten rule rows and the evaluator. Rules needing code: `R9` and `R10` are named procedures and the candidate-set and `flag_value` functions are code; this contradicted the statement that no rule logic is outside data (finding 19, now stated). R1..R8 need nothing outside the expression language.
- R9 re-check and in-flight behaviour: stamps, `stale_recheck`, acceptance outcome table, tightening sweep, revoked and suspended handling. Found the fast path blind to template and kill-switch changes, no R9 at lease, and no `hold` branch (findings 14, 15, 16).
- Allowlist against FD 5.7(5): A01 (P0, L0) and A02 (P1, L1 or L2) times S0 or S1 times M0 or M1 give 4 + 8 = 12 active tuples, arithmetic correct and equal to the two profiles of FD 5.7(5). Locked rows L01 and L02 are `P2` and `P3`; unlocking is a loosening. No machine check caps active profiles at two (logged, finding 28).
- Rejection reasons: all ten `copy.policy.R<n>.<slug>` keys exist in `en` and `fa` with the review marker; no text uses "guarantee".
- Injection screening: wrapper token (12 Crockford base32 characters = 60 bits, arithmetic correct), required clauses, normalization steps, and every screening rule read for executability (finding 18). Walked `T-policy-01`..`T-policy-47` against the rule rows; all agree except `T-policy-45` (finding 24).
- Parameters and error codes: `LAUNCH_GATE_CLOSED`, `KILL_SWITCH_ENGAGED`, `POLICY_REJECTED` exist in S0.11.3; S14 used `FORBIDDEN` for them (finding 23).
