# Audit A05: spec/05a-entities.md

Reviewer: independent (cell C-046). Files audited: `spec/05a-entities.md` (1917 lines at audit start). Compared against `spec/00-conventions.md` (S0, read in full except the last ~50 lines of 0.13) and, for lookups and key names, `spec/05b-state-machines.md` (lines 1-220 and 520-640 only).

## Checked

- Entity coverage: all 25 entity groups of the checklist are present (Member, Device, Invite, Template, Job, Cell, Lease, Submission, VerificationRecord, GoldCell, Audit, LedgerAccount, LedgerEntry, Escrow, Reserve, Policy, ServiceRegistryEntry with TermsCopy and dated FlagAnswer, Report, Appeal, Reservation, Team, Badge, ChangeLogEntry, LaunchGateItem). The catalogue in S5.4 has 57 rows, equal to S0.7 (28 + 29); table names, prefixes and retention classes match S0.7 row by row.
- Enum and state names against S0.8 and S0.9: Job (15 states), Cell (12), Lease, Submission, Audit, Escrow, Reservation, Report, Appeal, TemplateVersion.review_status, service review_status, member status and tier, cell_kind, verification method and outcome, ledger account, entry and txn kinds, the 13 flag keys, flag answers, `closure_reason` (S0.9.2 list), feature-flag and kill-switch keys.
- Parameter names: every `area.name` referenced in the file was looked up in S0.10.6 Tables A to C; none is missing or misspelled (S5.2.5 local enums are correctly marked [A]).
- Arithmetic: `price = 1000000 + v + lambda`, `escrow_ucr = N * price`, `planned_primary + planned_pool + planned_levy = escrow_ucr`, `verification_pool_cells = floor(N * v_ppm / 10^6)` agree with S0.6.1; AC-data-11 (276,000,000 = 264,000,000 + 12,000,000, refund 0) reproduces the S0.6.1 table for N=240, v=100,000, lambda=50,000. The ID regex of `is_id()` equals S0.6.3. The `vol_` handle (16 bytes = 32 hex) equals S0.6.4 and the DDL `CHECK`.
- Foreign keys: every `REFERENCES` target in S5.14 is a real table of the catalogue and a real column (`id`); all ids are `text`, so types match across tables. Circular FK pairs are now all deferrable (finding 8).
- Idempotency claims: `ledger_transactions.natural_key` UNIQUE, `cells.credit_txn_id` UNIQUE, `leases` UNIQUE `(cell_id, attempt)` plus the partial unique index on active leases, `submissions.lease_id` UNIQUE, `escrows.job_id` and `reservation_id` UNIQUE, `reverses_entry_id` UNIQUE, `badge_awards` unique pair, `experiment_assignments` unique pair: each supports the claim made for it.
- Append-only modelling: IMM and CHN tables have no `updated_at`; corrections are `supersedes_id`, `reversal`, new version or new revision (S5.4 and S5.15.3); `ledger_entries` has the mutation trigger and the insert-only-via-`ledger_post()` trigger; chain formula and genesis value are consistent between S5.9.2, S5.14.6 and S5.15.2.
- Ledger writer (S5.14.6) against the entry-type rule table (S5.14.7) and S0.8.5: all 11 entry types, debit and credit account types and lot effects agree; the zero-sum identity matches the sign rules of the five account types.
- Data minimization: no table or column stores an IP (only keyed hashes with TTL), a clear e-mail, a provider credential, a chat URL, a provider session, a user-agent or a fingerprint; `uploads`, `submissions`, `events` and `reports` carry no such field. Volunteer hash scope (S5.3.2) is system-wide per key version, stored only on `submissions` and the internal manifest, and the manifest export is redacted. Rotation and linkability limits are stated. Retention is stated for every entity (S5.4 catalogue plus S5.15.4); purge columns exist for each `job_bound` payload.
- Lookups named in the S5.22 and S5.23 transition tables that were read: lease reaper, cell queue, concurrency caps, reservation caps, referral hold, service review due, kill-switch and flag views all have indexes; timer lookups that lacked one were added (finding 9).
- Ground rules: no provider fact stored as a constant; flag answers are dated reviewer data, `unknown` evaluated as `no`; manifest says "declared"; numbers are formulas or reference parameters; no automation of volunteer accounts anywhere in the model.
