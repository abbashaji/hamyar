## Checked

- Recovery key (10a 10.4): payload 128 bits from the OS CSPRNG with a refusal path instead of a weak fallback; checksum 22 bits gives 150 bits = 30 characters = 6 groups of 5 (correct); undetected typo 2^-22 (about 2.4 in 10 million, correct); 2^128 / 10^12 = 3.4 x 10^26 s, about 1.1 x 10^19 years (correct); the secret is never stored, only the derived public key; rotation rules (confirmed vs unconfirmed, after recovery) are consistent with 10.6 and 10.8.
- Device link (10.7): 128-bit secret = 26 Crockford characters (correct); single-claim, SAS role stated honestly; session, key chain and recovery abuse table (11 rows) read against 10.8 flow; no step contradicts another except the items fixed below.
- Sessions (10.13): TTL arithmetic 30 d = 2,592,000 s and 90 d = 7,776,000 s match constraint C9 against `retention.session_days` = 90.
- Admin authentication (10.12): no shared password, no TOTP, no SMS; WebAuthn on a separate origin; two-person protocol binds the approval to `params_hash`; sign-count clone handling present.
- Threat model (10b 10.12): all prompt rows present with a residual risk each: forged results THR-01/02, credit farming THR-03/04, fake accounts and invite trees THR-05/06, malicious requesters and inputs THR-07/08, prompt injection THR-09, XSS and injection THR-11 (plus THR-10), ledger tampering THR-12, insider and operator THR-13, account takeover THR-14/15/16, de-anonymization THR-19, compelled disclosure THR-20, DoS THR-22, reviewer capture THR-23/24/25.
- Secrets inventory (10b 10.14.2): `PANEL_TOKEN`, `ADMIN_TOKEN`, `GITHUB_TOKEN`, `MCP_AUTH_TOKEN` (and `EXT_TOKEN`) present with exact rotation steps; rotate-before-exposure rule with a defined exposure event and launch-gate item `g1.secrets_rotated` that blocks `launch.members_may_join`; compromise response and hygiene present.
- Exposure formulas in 10a 10.10 (2 x 3 = 6 credits per tree per day, 20 x 3 = 60 per day) are arithmetically correct for the stated defaults.
- Provider rules: no credential, session or chat page is stored; no automation; no circumvention feature; copy uses `declared`, never `guaranteed`.
- Salt scope of the volunteer handle: it is a keyed HMAC with one system-wide key per version (not per job), linkable across jobs within a version, unlinkable across versions after key destruction; this matches `S5.*` 5.3.2 and S0.6.4 and is now stated in 10a 10.15.1.
- Entities read against the logging table: `Member`, `MemberKey`, `Device`, `Session`, `Invite`, `AdminUser`, `AdminCredential`, `AdminAction` in `spec/05a-entities.md` (first 470 lines).
